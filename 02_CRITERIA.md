# Решение по критериям задания

| Критерий | Что представлено | Подтверждение и границы |
|---|---|---|
| Качество прогноза, до 10 баллов | Обученный WeatherEnsemble; почасовой прогноз | Официальный итоговый score не приложен. Качество не подменяется результатом нагрузочного теста |
| Данные и применимость, до 8 баллов | Погода ERA5, календарные признаки, сведения об окружении остановок, сценарии событий | Реестр источников приложен. Прирост качества каждого фактора для текущей версии не подтверждён парным отчётом |
| Архитектура и производительность, до 5 баллов | Docker, REST API, разделение модулей, реальные HTTPS-замеры | 268 RPS для прогнозов; ограничения смешанных/тяжёлых сценариев описаны. Горизонтальное масштабирование требует общей очереди |
| Функциональность, до 4 баллов | День/неделя/месяц/год, маршрут/остановка/участок, карта, CSV/PDF | Год — качественная экстраполяция; остановки — условное распределение, геометрия неполна |
| Бизнес-ценность, до 2 баллов | Сравнение сценариев, выявление перегрузки, условный резерв | Рекомендации требуют проверки расписания, парка и диспетчером |
| Питч, до 10 баллов | Понятный сценарий демонстрации и сводный отчёт | Баллы за выступление не присваиваются по наличию файлов |

## Нефункциональные требования

- Один контейнер приложения: 2 CPU и 2 ГиБ RAM подтверждены данными работающего контейнера. HTTPS-прокси — отдельный инфраструктурный компонент.
- Сотни RPS и p95 <200–300 мс: подтверждены для выдачи прогнозов. Для смешанной нагрузки 200/300 RPS и тяжёлых событий — не подтверждены.
- CPU 60–80%: в длительном тесте 50.04% общей квоты. Память стабильна в пределах наблюдаемого 10-минутного интервала; swap 0 в отсчётах. Не заявляется длительная многосуточная проверка.
- Надёжность API: 31 проверка пройдена; повторный запрос здоровья после ошибок успешен. Визуальная понятность сообщений пользователю не оценивалась автоматическим HTTP-тестом.
- Горизонтальное масштабирование: архитектурная возможность чтения несколькими копиями; общая очередь заданий и отказоустойчивость ещё требуют реализации.
- Приём данных: пакетный CSV, не непрерывный потоковый HTTP-контур.

Основание: приложенные требования, страницы 3, 5 и 6. По странице 5 жюри принимает честные заявленные измерения с подтверждением; отдельный нагрузочный тест жюри не проводится. Отчёт не утверждает получение максимальных баллов.
